# TG-Agent — Telegram News Monitor

**TG-Agent** — автоматизированный мониторинг новостей в Telegram, предназначенный для отслеживания блокировок интернет-ресурсов, ограничений доступа к интернету и деятельности Роскомнадзора в России.

Приложение собирает публикации из заданных Telegram-каналов, предварительно фильтрует их по ключевым словам, анализирует содержание с помощью языковой модели (LLM) и отправляет релевантные новости в указанный Telegram-чат.

## Возможности

- **Мониторинг Telegram-каналов.** Сбор последних публикаций из списка заданных каналов.
- **Фильтрация по ключевым словам.** Предварительный поиск сообщений, связанных с блокировками и ограничениями интернета.
- **Анализ с помощью LLM.** Определение тематической релевантности публикаций с использованием модели через OpenRouter.
- **Автоматическое формирование выжимки.** Получение краткого содержания новости и объяснения её значимости.
- **Отправка уведомлений.** Передача отобранных новостей в заданный Telegram-чат через Telegram Bot API.
- **Защита от дубликатов.** Использование SHA-256-хешей для предотвращения повторной обработки одинаковых публикаций.
- **Сохранение прогресса.** Запоминание последних обработанных сообщений по каждому каналу.
- **Автоматический запуск по расписанию.** Периодическое выполнение мониторинга с интервалом 10 минут.

## Как работает приложение

Работа приложения состоит из нескольких последовательных этапов.

1. **Сбор публикаций.** Telethon подключается к Telegram и получает последние сообщения из указанных каналов.
2. **Первичная фильтрация.** Тексты проверяются на наличие заданных ключевых слов и выражений.
3. **Проверка дубликатов.** Для публикаций рассчитывается SHA-256-хеш. Уже обработанные сообщения повторно не анализируются.
4. **Анализ содержания.** Подходящие публикации передаются языковой модели через OpenRouter.
5. **Определение релевантности.** Модель определяет, относится ли сообщение к тематике мониторинга.
6. **Формирование результата.** Для релевантных публикаций создаются краткая выжимка и объяснение причины отбора.
7. **Отправка уведомления.** Результат передаётся в целевой Telegram-чат.

## Технологический стек

| Технология | Назначение |
|---|---|
| Python | Основной язык разработки |
| Telethon | Получение публикаций из Telegram |
| OpenRouter | Доступ к языковым моделям |
| LLM | Анализ содержания и определение релевантности |
| Telegram Bot API | Отправка уведомлений |
| python-dotenv | Загрузка конфигурации из `.env` |
| JSON | Локальное хранение состояния и обработанных публикаций |
| asyncio | Асинхронное выполнение задач |



### Назначение основных файлов

| Файл | Описание |
|---|---|
| `config.py` | Загрузка настроек, переменных окружения, списка каналов и ключевых слов |
| `tg_collector.py` | Подключение к Telegram, получение и первичная обработка публикаций |
| `llm_processor.py` | Анализ публикаций с помощью языковой модели |
| `telegram_sender.py` | Формирование и отправка уведомлений |
| `state.py` | Управление состоянием и защитой от дубликатов |
| `run.py` | Основной сценарий однократного запуска |
| `scheduler.py` | Периодический запуск мониторинга |
| `tests/` | Тесты отдельных компонентов и сценариев |

Файлы `.env`, `state.json`, `processed.json` и файлы сессий Telegram создаются или используются локально и не должны публиковаться в открытом репозитории.

## Требования

Для запуска необходимы:

- Python 3.10 или новее.
- Аккаунт Telegram.
- Telegram API ID и API Hash.
- Telegram-бот с токеном.
- Целевой Telegram-чат, в который бот сможет отправлять сообщения.
- API-ключ OpenRouter.
- Доступ к выбранной языковой модели через OpenRouter.

## Настройка

Перед первым запуском необходимо создать файл `.env` в корневой папке проекта.

Пример конфигурации:

```env
# Telegram API
TELEGRAM_API_ID=your_api_id
TELEGRAM_API_HASH=your_api_hash
PHONE=your_phone_number

# Telegram channels
TELEGRAM_CHANNELS=@channel1,@channel2,@channel3

# OpenRouter
OR_API_KEY=your_openrouter_api_key
OPENROUTER_MODEL=your_model_name

# Telegram Bot
BOT_TOKEN=your_bot_token
TARGET_CHAT_ID=your_target_chat_id
```

### Получение Telegram API ID и API Hash

1. Перейдите на https://my.telegram.org/.
2. Авторизуйтесь с помощью своего Telegram-аккаунта.
3. Откройте раздел API development tools.
4. Создайте приложение.
5. Скопируйте `api_id` и `api_hash` в файл `.env`.

### Настройка Telegram-каналов

В переменной `TELEGRAM_CHANNELS` указываются каналы, публикации которых необходимо отслеживать.

Пример:

```env
TELEGRAM_CHANNELS=@channel1,@channel2,@channel3
```

Каналы должны быть доступны используемому аккаунту Telegram.

### Получение API-ключа OpenRouter

1. Перейдите на https://openrouter.ai/.
2. Создайте аккаунт.
3. Получите API-ключ.
4. Укажите его в переменной `OR_API_KEY`.
5. Выберите доступную модель и укажите её идентификатор в `OPENROUTER_MODEL`.

### Настройка Telegram-бота

1. Создайте бота через [@BotFather](https://t.me/BotFather).
2. Получите токен бота.
3. Добавьте бота в целевой чат или канал.
4. Предоставьте необходимые права на отправку сообщений.
5. Укажите токен в `BOT_TOKEN`, а идентификатор чата — в `TARGET_CHAT_ID`.

**Важно:** не публикуйте `.env`, API-ключи, токены и файлы Telegram-сессий в GitHub.

## Запуск

### Однократный запуск

Для выполнения одного цикла мониторинга:

```bash
python run.py
```

Приложение получит публикации, обработает их и отправит релевантные новости в целевой Telegram-чат.

### Автоматический мониторинг

Для постоянной работы с периодическим запуском:

```bash
python scheduler.py
```

По умолчанию новый цикл начинается каждые 10 минут.

Если предыдущий цикл выполнялся дольше 10 минут, следующий запуск начинается после его завершения.

Для остановки нажмите:

```text
Ctrl + C
```

## Хранение состояния

Приложение использует два локальных JSON-файла.

### `state.json`

Хранит ID последних обработанных публикаций для каждого Telegram-канала.

Это позволяет продолжать мониторинг с сохранённого прогресса после перезапуска приложения.

### `processed.json`

Содержит SHA-256-хеши обработанных текстов.

Используется для предотвращения повторного анализа одинаковых публикаций, в том числе опубликованных в разных каналах.

Оба файла создаются автоматически при необходимости.

**Важно:** при удалении этих файлов приложение потеряет сохранённый прогресс и информацию об уже обработанных публикациях.

## Тестирование

В проекте предусмотрены тесты для проверки отдельных сценариев.

Для запуска тестов с помощью pytest:

```bash
pytest
```

Некоторые тесты требуют доступа к Telegram и OpenRouter.

Обрати внимание: `tests/test_sender.py` отправляет реальное тестовое сообщение в Telegram. Запускай его только тогда, когда отправка тестового сообщения действительно нужна.

`tests/test_llm.py` также выполняет интеграционный сценарий, связанный с Telegram, а не только изолированную проверку логики.

## Ограничения текущей версии

Текущая реализация представляет собой MVP и имеет ряд ограничений:

- Источниками публикаций являются Telegram-каналы. Мониторинг сайтов и RSS пока не реализован.
- За один цикл из каждого канала загружается не более 10 последних сообщений.
- Для первичного отбора используется фиксированный список ключевых слов.
- Анализ LLM зависит от доступности OpenRouter и выбранной модели.
- Состояние и история обработки хранятся локально в JSON-файлах.
- При ошибке отправки уведомления уже обработанная публикация не ставится автоматически в очередь повторной отправки.
- Для непрерывной работы приложение должно оставаться запущенным на компьютере или сервере.
